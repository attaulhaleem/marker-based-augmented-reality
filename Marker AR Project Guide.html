01Brief and scope

Goal

  • Detect a planar marker (e.g. newspaper / journal page) in the webcam stream
  • Register it with a homography, replace it with a substitute image
  • Method: keypoints → descriptors → matching → filtering → robust transform estimation

05Pipeline map

Same three components as the course: detection → description → matching (D4 p.10, D5 p.2), then verification by a global geometric relation (D5 p.31, 40).

StepOpenCVOutputVisual check
1. FeaturesdetectAndComputeKeyPoint list + descriptor arraydrawKeypoints, rich flag
2. MatchingBFMatcher / FlannBasedMatcher, match / knnMatchDMatch listdrawMatches, all matches
3. FilteringOwn code on distancesShorter DMatch listdrawMatches, kept only
4. AlignmentfindHomography, warpPerspective3×3 H + inlier maskMarker outline + blended overlay
5. RefinementSteps 1 to 4 again on the rectified frameH·HrLess jitter, tighter outline
  • Once, at start or when detector settings change: detect + compute on the marker
  • Every frame: detect + compute on the frame → match → filter → H → validate → warp + blend
  • Convention used here: query = marker, train = frame; H maps marker pixels → frame pixels

Key data classes (compare with the SIFT output list on D5 p.18):

  • KeyPoint: pt (position), size (patch scale), angle (dominant orientation), response, octave
  • Descriptors: n × 128 float array (SIFT) or n × 32 / 61 / 64 byte array (ORB / AKAZE / BRISK)
  • DMatch: queryIdx, trainIdx, distance

Not in the slides: binary descriptors.
  • Idea: compare intensities of point pairs inside the patch → one bit per pair → bit string; distance = Hamming (count of differing bits, computed with XOR), very fast
  • ORB: FAST corners on an image pyramid, ranked by Harris score (D4 p.42–45), orientation from intensity centroid, rotated BRIEF, 256 bits
  • BRISK: corner detection in scale space, fixed circular sampling pattern, 512 bits
  • AKAZE: nonlinear (edge-preserving) scale space instead of Gaussian, Hessian-based detector, M-LDB binary descriptor
  • Read: OpenCV docs pages for cv::ORB, cv::BRISK, cv::AKAZE, and the Python tutorial "Feature Detection and Description"

Not in the slides.
  • Homography: 3×3 matrix up to scale → 8 degrees of freedom; each match gives 2 equations → 4 matches minimum; solved linearly (DLT) then refined on inliers
  • Least-Median (LMedS): minimises the median residual; no threshold to tune; needs more than 50 % inliers
  • PROSAC (cv.RHO): RANSAC that samples the best-ranked matches first → faster; pass matches sorted by distance

Estimation

src = np.float32([kp_m[m.queryIdx].pt for m in good]).reshape(-1, 1, 2)
dst = np.float32([kp_f[m.trainIdx].pt for m in good]).reshape(-1, 1, 2)
H, mask = cv.findHomography(src, dst, cv.RANSAC, ransacReprojThreshold=3.0,
                            maxIters=2000, confidence=0.995)
Method flagWhat it isExpect
0Least squares on all pointsBreaks with any wrong match (D6 p.55)
cv.RANSACRandom sample consensusDefault choice
cv.LMEDSLeast median of squaresFails with heavy clutter
cv.RHOPROSAC-basedFaster with many outliers
  • Sliders: method, reprojection threshold (1 to 10 px), max iterations, minimum inliers
  • Affine comparison (D5 p.42–45): cv.estimateAffine2D(src, dst, method=cv.RANSAC). Fine when frontal, wrong under tilt. One experiment is enough

Validate H before drawing

  • H is None or inliers below minimum → reject
  • Project the 4 marker corners with cv.perspectiveTransform
  • Reject if the quadrilateral is not convex (cv.isContourConvex) or its area is tiny / larger than the frame
  • Rejected frame → show the plain frame (optionally reuse last valid H for a few frames)

Augmentation

  • Resize substitute image to the marker image size (same coordinate system as H)
  • warped = cv.warpPerspective(substitute, H, (frame_w, frame_h))
  • Mask: warp a white image of marker size with the same H
  • Inside the mask: fusion = (1 − α) · warped + α · frame; α slider in 0 to 1. α = 0 → full replacement
  • Course helper: overlay_uchar_image in OpenCV_Image_Utilities.py (NextCloud, named in the brief)
  • Debug view: warp the marker itself with α = 0.5. Ghosting shows misalignment directly

What to observe

  • Inlier count and inlier ratio per frame
  • Outline stability on a still scene (jitter)
  • Reprojection threshold: too small → few inliers, jitter; too large → wrong matches accepted, skewed outline
  • Largest tilt angle and distance at which tracking still holds

10Step 5: Refinement Optional

Slides: same scheme as iterative flow estimation, D6 p.63 (estimate → warp → estimate the residual → compose). Coarse-to-fine idea: D6 p.66–68.

  • Rectify the frame into marker coordinates: cv.warpPerspective(frame, np.linalg.inv(H), (marker_w, marker_h))
  • Run steps 1 to 4 again: marker → rectified frame. Result: residual Hr, close to identity
  • Final transform: H_final = H @ Hr, then divide by H_final[2, 2]
  • Why it can help: rectified view has almost no perspective distortion → more and better matches
  • Cost: roughly doubles processing time. Put it behind a toggle
  • Measure: inliers and jitter with / without; frame rate with / without
Check the order. H @ Hr (the brief's HHr) is correct with the convention above (Hr estimated in marker coordinates). Test: with refinement on, the outline must not jump.

Synthetic test with ground truth Quantitative

  • Pick a known homography H_gt (move the 4 corners), warp the marker onto a background photo
  • Apply one degradation at increasing levels: scale, rotation, tilt, brightness / contrast αL + β (cv.convertScaleAbs, D2 p.40–41), Gaussian blur, Gaussian / impulse noise (D2 p.15–19), black rectangle covering x %
  • Run the pipeline, compare projected corners: error = mean distance between H_est and H_gt corners
  • Ground truth also labels each match: correct if H_gt maps the marker keypoint within 3 px of its matched frame keypoint → true precision and recall per filter
  • Plot error and success rate vs. degradation level, one line per detector

Expected outcomes, to confirm or refute with your data

Hypotheses only. Report what you measure, including surprises.
  • Features: detector type and number of keypoints are the largest lever on both robustness and speed
  • SIFT: most robust to scale and tilt, slowest. ORB: fastest, weaker far away and at steep angles. AKAZE: in between
  • Matching: correct norm is essential; BF vs. FLANN matters little at a few thousand descriptors
  • Filtering: ratio test more reliable than global threshold; r is the most sensitive single slider
  • Alignment: robust estimator is mandatory; reprojection threshold trades jitter against acceptance
  • Marker: texture richness matters as much as any algorithm choice

  1. Setup: hardware, Python and OpenCV versions, marker and substitute images, how to run
  2. Pipeline: the brief's 4-block diagram, conventions, code structure (D12 p.15–18)
  3. Per block (×4): options tried → parameters → evidence (plot / screenshot) → choice and reason → most influential parameter
  4. Robustness: one short paragraph + figure for each of: marker features, viewpoint, lighting, occlusion, background
  5. Final configuration: table of chosen methods and values, FPS reached
  6. Limits and improvements: failure cases with screenshots, what would fix them
